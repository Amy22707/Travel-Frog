# 庭院串门旅蛙

普通版和图鉴版使用相同的串门流程：本地模拟的过路旅蛙在庭院吃东西，离开后留下礼物，点击领取。名称为“过路旅蛙”，不使用真实玩家的名字、账号或地理位置。

## 正式客户端依据

原始客户端包含 `VisitorData`、`VisitorModel`、庭院 `updateVisitor`、`VisitorView` 与 `VisitorGiftView`。`visit.load` 携带来访青蛙、省份、食物、垫子和到期时间。`visitors_json.json` 提供吃饭动作和省份奖励；`gameplay_json.json` 中“串门”的 `DurationFloor`、`DurationUpper` 均为 30 分钟。

首次领取某省份的回礼会记录 `visit.load.acquire`，显示对应省花；重复省份按 `OtherGiftID` 和数量区间发放奖励。省花收录不是花瓶可插入的消耗花朵。来访结束后的礼物在领取前保留，重复点击不重复发奖。

## 离线规则

完成新手引导后开始调度。首次安排及每次领奖后随机等待 2–5 天，下次登录同步时出现。调度时间保存在各自存档中，反复登录不重抽时间；已有来访或未领礼物不被新访客覆盖。吃饭时长随机为 20–60 分钟，到期后按原 UI 切换为回礼。

来访间隔、随机停留时长、模拟来源和地区选择是本地规则，不是已恢复的官服匹配算法。正式配置停留时长为 30 分钟，离线版按用户要求作随机化。网上检索未获得能验证官服匹配频率的说明；常见的 3–4.5 小时攻略说的是日版小动物来访，不用于本系统。客户端能确认串门、吃饭、回礼，但不能据此断言官服如何按真实旅行疲劳或玩家关系匹配。

这套系统与跳跳、困困、胖胖的邻居来访以及礼品盒的旅友赠礼各自独立，不消耗礼品盒照片、特产或自己的旅行背包。

源码改变后需要重新构建 Windows、安卓及网页测试包。公开发布仍以用户验收和明确同意为前提。

## 测试

5 项专门回归覆盖无需礼品盒也能来访、随机间隔和停留、重启稳定、提前领取拦截、一次性省花和重复来访奖励，与其他存档及玩法测试合计 25 项通过。

普通版 Chromium 和图鉴版 WebKit 的本机 Python 运行环境均实际生成并显示来访青蛙。Windows 测试使用独立无头浏览器，验证正式动画、来访信息窗、回礼窗和省花领取的存档落盘；不打开可见窗口或模拟器，不修改个人进度。
