# 跨平台代码审查

测试候选：v0.2.1。源码仓库保持私有，Windows、安卓与网页文件仅存入私有草稿；公开网站不展示游戏入口。

## 审查范围

本轮审查覆盖独立 Windows 入口与关闭流程、存档管理、安卓资源服务器和原生文件接口、Pyodide Worker、协议桥、IndexedDB 持久化、PWA 离线缓存、安装包构建与发布脚本，以及 Studio 入口和用户教程。共享服务端重点核对存档读写、协议收发、初始化迁移和双版本隔离，不重写原客户端或已完成的玩法系统。

普通版与图鉴版分别持有存档。手机和网页在设备本地运行同一套服务逻辑，不需要连接电脑或官服；Windows 使用本机服务和独立游戏窗口。

## 行为与修正

- 网页中的 HTML、JS、配置 JSON 与 Python 程序包联网时优先读取新版本，断网时使用缓存；图片等固定资源保留缓存优先。更新程序不要求清理网站数据或删除存档。
- 安卓与网页可通过“导出上次导入前的备份”取回最近一次被覆盖的进度，不需要 root 或访问应用私有目录。该备份与当前存档使用同一种 `.frogsave` 格式。
- 从游戏回到手机起始页会重新读取名字和存档状态，改名结果即时显示。JSONL 文件后缀大小写均可识别；协议会话退出时清理连接记录并同步存档。
- Windows 从长时间休眠恢复时给浏览器重新发送心跳的时间；导出期间不会停止关闭监测，待导出完成后仍可正常退出本地服务。
- 安卓保存文件取消或写入失败时，向照片界面返回失败结果并释放待保存内容，不留下未结束的保存操作。
- 上传工具默认保留草稿，发布必须明确传入 `--publish`；工具不会更改仓库可见性，也不会部署网站。

## 验证结果

- 20 项 Python 回归通过，覆盖普通版与图鉴版隔离、照片图层导入导出、覆盖前备份、单写入锁、历史存档修复隔离、Windows 生命周期、花圃和活动规则。
- Chromium 普通版、WebKit 图鉴版分别完成：新建进度 → 进入游戏 → 改名 → 返回存档页 → 导出 → 再次进入并改名 → 导入旧备份 → 取回被覆盖进度 → 重载 → 完整缓存后断网进入游戏。两组均无脚本错误。
- 缓存中放入旧版程序的测试标记后，联网重载能取得新程序；断网重载保留当前进度。
- 两个重新构建的 Windows 服务端与客户端均能进入游戏。图鉴版相册、家具、手工品、照片和美好瞬间入口可打开；工具列表滚轮从 0 滚动至约 669，未发现脚本或资源加载错误。
- 安卓图鉴版覆盖安装保留已有测试进度，并能继续进入庭院，内部版本为 2.0.1、versionCode 为 3。两个 APK 均完成签名与打包。
- 两个 Windows ZIP、两个 APK、网页 ZIP 均未包含个人存档、原始抓包、运行日志或原开发账号的历史相册数据。原有普通版与图鉴版存档未修改，主页中的其他未提交编辑保留。

## 用户验收

在实际使用的 Windows 电脑、安卓手机与 iPhone / iPad 上核对安装、照片显示与保存、存档迁移、关闭后重新进入，以及离线长时间游玩。iOS 使用 Safari 添加到主屏幕，不是 IPA 安装包；请在主屏幕应用内导入并下载完整离线资源。

移动端重点核对“导出上次导入前的备份”：导入另一份进度后导出该备份，重新导入应恢复覆盖前的进度。设备不会自动同步，换机前应手动导出。

介绍页和网页游戏可在本机运行。在 Windows CMD 中执行：

```bat
cd /d D:\PKU\CODE\frog
python -m http.server 52360 --bind 127.0.0.1 --directory release\TravelFrogWeb
```

打开 `http://127.0.0.1:52360/`；该服务只允许当前电脑访问，关闭 CMD 或按 Ctrl+C 停止。iPhone 的完整离线验收仍需要可访问的可信 HTTPS 测试环境，不能把本机回环地址当作手机地址。

主页公开主分支不再包含本次网页资源发布与撤回的两个提交。远端与本地分支均位于发布前的 `915c141`，25 个本地修改及未跟踪文件的内容保持不变。完整历史恢复包与这些文件的副本保存在 `.build/20261024-homepage-history-backup/`，不进入公开仓库。

分支历史清理不保证 GitHub 缓存、旧提交对象或第三方已缓存的内容立即失效。个人存档未进入这些公开提交；测试程序继续保留在私有草稿中。
